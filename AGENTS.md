# Notework agent instructions

This project uses SvelteKit 3 and Svelte 5, with Vite and TypeScript. Configuration belongs in `vite.config.ts` (SvelteKit 3 does not use `svelte.config.js`). Check installed package types and current official SvelteKit documentation before changing framework configuration.

- Keep filesystem access browser-side. In the native app (`native/`, Tauri), machine folders use the app's Rust commands and Notework's own folder browser instead of the browser picker; contents are read and written only below folders the person selected there. Machine files are limited to user-selected handles; request write permission only from an explicit Create, Save, or Rename action. Children inherit the parent folder’s storage: machine folders create machine children and browser folders create OPFS children. New resources at the virtual root use native storage, the default: the app-owned `documents` folder on disk in the native app, and app-owned OPFS in the PWA. Directed links may cross storage sources and are not parent-child relationships. Never add a server endpoint exposing the host filesystem.
- Import Keyflow components and styles from the `@legitminh/keyflow` library dependency. Use Keyflow controls for action buttons, including form submissions; preserve Enter and native validation in forms. Do not copy library source into this repository; keep app policies such as native scrolling in Notework.
- When working on Keyflow integration or keyboard UI, check upstream for a newer version and update if available. Review its changes, run `pnpm update:keyflow`, and commit the exact dependency pin, lockfile, and matching build approval together. Verify keyboard input, layouts, modal shortcuts, and native scrolling after upgrading.
- Design style: user-facing text is uncapitalized. Default text, button and menu names, labels, headings, instructions, status and error messages, and default asset names (e.g. `layer 2`) start in lowercase, including each sentence. Keep proper nouns, product and key names, and acronyms as written (GitHub, Notework, Keyflow, Vim, Chrome, Ctrl, Shift, PDF, SVG, single-letter keys).
- Scrolling must remain native; do not enable lockstep or honor a saved lockstep preference.
- Root is a virtual folder with children from multiple sources and no filesystem resource of its own. Filesystem direct children and configured directed links define transitions; parent navigation is not part of search traversal. Search and link suggestions follow the active root graph. Removed root items and their descendants must stay excluded even if source handles, cached nodes, or old directed links remain; explicitly reconnecting them restores searchability.
- Handles, resource URIs, and directed graph metadata are saved in IndexedDB; new document contents live in native storage (on disk in the native app, OPFS in the PWA). Do not upload file contents. Hide non-text resources and `.git` metadata. Prune confirmed missing resources and all their graph edges; permission denial is not deletion.
- Run `pnpm check`, `pnpm build`, and relevant Playwright tests after functional changes. Browser fixtures must use isolated test storage, not personal filesystem paths.
- On macOS, after a functional change is verified, build the current native app with `pnpm --dir native build:desktop`, replace `/Applications/Notework.app` with that build, and relaunch it so the computer is running the latest build.
- Commit each finished, verified feature directly to `main` (one commit per feature) and push `main` to GitHub. Do not use a separate feature branch.
